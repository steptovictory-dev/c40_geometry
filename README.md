# c40_geometry

Воспроизводимое исследование геометрии авиационных метаданных C40 и восстановления траекторий между наблюдениями. Проект выделен из Approach Risk ver. 1.0 с сохранением соответствующей истории разработки.

## Зачем проводилось исследование

Перед использованием авиационных признаков важно понять, что именно измерено и насколько согласованы координаты, время и справочные данные. Исследование началось с точки входа в ASMA 40 NM: проверялись геометрические зависимости, исторические координаты аэропортов и сопоставление с публичными наблюдениями OpenSky. Затем возник отдельный вопрос: как восстанавливать положение между редкими наблюдениями и дает ли обучаемая поправка преимущество перед сильным простым методом?

## Что выполнено

- Аудит координатной сетки C40, азимута, расстояний на сфере и WGS84.
- Сверка восстановленных центров EGLL и EGCC с выбранными историческими AIP.
- Разбор радиальных отклонений и приведение наблюдений разных источников к одному времени.
- Эксперименты со скрытыми внутренними точками: ближайшее наблюдение, линейная интерполяция, постоянная скорость, кубический Эрмит и Ridge-поправки.
- Разделение по рейсам, выбор регуляризации по validation, проверки на других датах и расширение обучающей выборки.
- Исполненные ноутбуки, таблицы, графики и анализ ошибок; основной метод в проверенных условиях – Эрмит.

## Основные результаты

### Геометрический аудит

На 87 435 записях EGCC максимальная разница радиальных расстояний между сферой и WGS84 составила около **244,77 м**. Выбор метрики меняет состав диагностических случаев; пороги аудита не являются правилами удаления. Согласованность вычисленных метаданных не доказывает точность физического положения самолета.

Исторические координаты проверены для выбранных срезов EGLL и EGCC. Это не проверка всей истории всех аэропортов. В пилоте EPWA осталось межисточниковое расхождение около **43,04 км**; причина не установлена. Оно сохранено как открытый диагностический случай.

### Восстановление траекторий

| Проверка | Результат средней рейсовой ошибки |
|---|---|
| Начальная Ridge-поправка, 6 train / 2 validation / 2 test | Линейная интерполяция 316,4 м → поправка 124,6 м |
| Другая дата, 10 рейсов, фиксированная модель | Линейная интерполяция 420,5 м → поправка 173,2 м; на интервале 20 секунд поправка хуже |
| Финальное сравнение, 15 рейсов / 28 511 задач на двух новых датах | Модель этапа 11: 118,43 м; Эрмит: **105,34 м**; Эрмит + Ridge: 105,71 м |

Обучаемая поправка ухудшила результат Эрмита примерно на **0,35%**. Поэтому для проверенных условий оставлен более простой метод. Это содержательный результат сравнения с сильным baseline; универсальное превосходство любого метода не заявляется.

Средняя ошибка сначала вычисляется внутри каждого рейса, затем усредняется с равными весами рейсов. Скрытые точки – проверочные ответы OpenSky, не независимый эталон истинного положения. Линейная интерполяция и Эрмит используют оба конца интервала, поэтому эти эксперименты не являются ранним прогнозом движения в реальном времени.

## Данные и воспроизведение

Python ≥ 3.11. Из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/check_notebook_presentation.py
```

Последняя команда проверяет сохраненные выводы и оформление, не обучая модели. Для чтения результатов достаточно ноутбуков и reports. Для полного повторения нужны локальные траектории, справочные документы и исходные европейские таблицы. [Требования к данным](DATA_REQUIREMENTS.md).

Открывайте ноутбуки по порядку и выполняйте ячейки сверху вниз. Скрипты build_* могут пересоздавать ноутбуки; сохраненные ручные изменения нужно предварительно согласовать с генераторами. `verify_notebooks.py` исполняет код всех ноутбуков и не является только статической проверкой; запускать его следует при осознанном полном воспроизведении.

Сырые данные, модели в data, скачанная литература и Checkpoint остаются локальными. Git-клон не заменяет их резервную копию. Проект не является системой управления полетом или эксплуатационной оценкой безопасности.
